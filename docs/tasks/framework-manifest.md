## Behavioral contract (all mandatory)

- Accept negotiation: missing/empty/*/ only-*/ -> JSON; application/json (charset ok) and application/x-protobuf supported; q-values; tie -> JSON; q=0 or other-only -> 406 JSON not_acceptable.
- Request Content-Type: body-bearing ops accept JSON (charset ok) and protobuf only; non-empty body missing Content-Type or other type -> 415 JSON unsupported_media_type; dedicated empty request may omit Content-Type with empty body.
- Response codec follows Accept, not request Content-Type.
- Once Accept=protobuf, decode/validation failures return the operation-specific protobuf error response (HTTP 400); business failures keep their status but use protobuf error response. 406/415 always JSON.
- MULTI-FAILURE RULE (maintainer decision): if more than one failure condition is detected, return JSON 400 with the first detected error code.
- Identity/scope/quota: reuse resolveIdentity, assertRequiredScopes, getRemainTokens, tryConsumeTokens, recordApiKeyUsage, getClientIp. Do NOT call v1 executeApi. Failure charging mirrors v1. remain/cost/retry-after headers via useConfig().api.headers.
- JSON success: { ok: true, data, error: '' } (camelCase, optional unset omitted, known enums as lowercase strings, unknown response enum numbers preserved as numbers). JSON failure: { ok: false, data: userMessage, error: errorCode }. No meta in body.
- Protobuf success: XxxResponse oneof data + ApiMeta{remain,cost,retryAfter?}. Protobuf failure: oneof error + ApiMeta. 2xx only data; 4xx/5xx only error; HTTP status preserved.
- ETag: SHA-256 of final response body bytes; `"v2-json-<16hex>"`, `"v2-proto-<16hex>"`, raw `"v2-raw-<mimeSlug>-<16hex>"`. No 304 handling.
- Vary: merge 'Accept' without overwriting. Raw media keep media Content-Type + ETag.
- HEAD: full GET semantics, no body, charge exactly once. OPTIONS must not reach executor (middleware); if it does, 204 without auth/quota.
- Unknown JSON/protobuf request fields ignored; declared fields strict; unknown request enum string -> 400.
- v2EnumJson via protobuf-es reflection: request maps lowercase strings to enum numbers (including 'public' -> PUBLIC number); response emits known numbers as lowercase strings, unknown numbers as numbers.
- Errors: ApiRequestError -> its status/errorCode/userMessage/retryAfter; else 500 internal_error '服务内部错误，请稍后再试' with operation-name logging.
- CORS via existing applyApiCorsHeaders for cors ops; CSRF via nuxt-security (nothing extra).
